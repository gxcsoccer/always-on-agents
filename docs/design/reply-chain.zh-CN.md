# 把整条回复链交给模型

状态：第一步（3.6）已在 PR #47 实现并经 Codex 复核；第二步待做。3.3 的放宽用户已确认，属于第二步。

## 1. 要解决的问题

2026-11-24 在内部群里的实际操作：

1. 用户贴了一篇文档并 @ 机器人，机器人读了并总结。
2. 用户**回复**那条消息说"说了啥？"，没有 @，机器人收不到。
3. 用户再**回复**"说了啥？"这一条，只 @ 了机器人，没有别的字。

第 3 条到达时正文是空的。系统取回了被回复的那条（"说了啥？"），但只取这一层：它回复的是哪条、那条里有哪篇文档，都不知道。模型只能反问"你想问哪篇"。

用户的要求：不要为"空消息""两层回复"写特判，让它更 agentic，也就是把上下文给够，由模型判断。

## 2. 现在是怎么做的

- 一条消息带着"我回复的是哪条"（`data.replies_to`）。
- 运行开始前，如果被回复的那条不在 Brain 的记录里，向 connector 要一次（`channel.quoted`）。只有同一个人、同一个群里他自己写的消息才给原文和里面的文档链接；别人的只说"有一条"。
- 模型在这条消息后面看到一行括号说明：回复的是他自己哪句话，或者回复的是 agent 哪个时间发的消息，或者是一条不给看的消息。
- 读文档的工具只认：这条消息自己贴的链接、被回复的那一条里的链接、他最近一天在这个会话里贴过的链接。

只有一层。

## 3. 方案

### 3.1 往上走整条链，由 Brain 来走

从这条消息回复的那一条开始，一条一条往上，直到链的起点，最多五层，整条链共用现有的三秒时限。每一层先查自己的记录，查不到才问 connector：

| 这一层是什么 | 怎么认出来 | 给模型什么 | 它回复的是哪条，从哪里知道 |
|---|---|---|---|
| 这个人自己写、机器人收到过的 | 收件记录里有，同一个会话、同一个人 | 原文（最多五百字）和里面的文档链接 | 那条记录自己的 `replies_to` |
| agent 自己发出去的 | "说过的话"里有这条的回执 | 当时送达的原文（按现有规则，已清理的只给时间） | 那条答复是回答哪条消息的：答复的投递地址里记着 |
| 记录里没有的 | 问 connector 要这一条 | connector 说是他本人写的：原文和链接。否则只有"这里有一条不给看的消息" | connector 一并返回 |

connector 的钩子仍然是"取一条消息"，只多返回两样：这条消息是谁写的（本人 / 这个应用自己 / 其他），以及它回复的是哪条。走链、限层数、限时间都在 Brain，不在 connector。别的 connector 不实现也不受影响。

走不完（超时、到了五层、某一层取不到）就停在那里，把已经拿到的交给模型，并说明"更早的部分没有取到"。

### 3.2 模型看到什么

在这条消息前面给出回复链，最早的在前，每条标明是谁说的：

```
回复链（最早的在前）：
1. 他本人：〈原文〉（链接：https://…/docx/…）
2. 你：〈你当时的答复〉
3. 他本人："说了啥？"
然后是这条消息：〈正文，可能是空的〉
```

别人的消息只占一行"（这里有一条别人的消息，不给你看）"。这条界限不变：以某个人身份行事的运行里，不放进群里其他人写的字。agent 自己的话只取自 Brain 自己"说过的话"的记录，不取 connector 送回来的文字。

链上的文字计入这一批消息的体积上限。

指示里加一句通用的话：消息本身没说清楚时，先看回复链；链上能看出在问什么就直接答，看不出再问。不写任何针对"空消息"的规则。

### 3.3 读文档的工具认整条链

"这个人指向了哪篇文档"从"被回复的那一条"扩到"链上他本人写的每一条"：

- 链上他本人贴过的链接，都算他指向的。
- 链上 agent 的答复如果当时是读某一篇写出来的，而那一篇是他本人贴过的，也算。
- 模型在调用时说明读哪一篇（现在就是这样传参的），工具核对这一篇确实在上面的范围里。

**相对现在的一处放宽（用户 2026-11-24 确认：放宽，让模型选）**：现在"被回复的那条里有两篇链接"时工具直接拒绝，让模型去问。按本方案，链上有多篇时由模型根据上下文选，拿不准它可以问，但工具不再强制拒绝。他在飞书里能打开什么没有变，用的仍是他本人的授权。但候选确实变多了：他很久以前贴的链接，可能因为今天的回复链第一次成为这次请求的候选。变的还有"选哪一篇"从规则交给了模型，选错的后果是读了他贴过的另一篇。

**界限（Codex 对 60bf2b4 的复核）：**

- 链上的候选只对**这一次请求**和它的授权后接着处理有效。不把旧链接记成"他最近一天贴过的"，下一条无关的追问借不到它。
- 只认 connector 核实过是他本人写的那些层里的链接，由工具核对模型传来的那一篇确在其中。
- agent 的答复这一层：它当时读的那一篇要算进候选，必须是**为同一个人**读的，并且那一篇是他本人贴过的（沿用现有的出处判定）。不从答复的文字里找链接。给另一个人的答复只作为上下文显示，不带来任何候选。
- 别人的消息：正文、链接、名字都不给模型，也不进候选。隔着别人的一条回复时，可以凭飞书给出的上一条编号继续往上找更早的本人消息。
- 每一层都核对同一个群、同一个应用、同一个组织、消息编号对得上，身份按最初的提问人判定。遇到已撤回、身份或会话说不清、进了话题、链成了环，就停在那里。

### 3.4 存什么

- 现有的 `data.quoted` 是一个对象（被回复那一层的原文和链接），已经存下来的消息按这个形状读。**不改它的形状**，更早的层另放一个字段（`data.chain`），老数据照样能读。
- 来自 Brain 自己记录的层只存指向（哪条收件记录、哪条说过的话），到给模型组装输入时才取原文。agent 的总结、取回来的整段链，都不写进长期的对话记录。各处原有的清理时机不变；指向的东西被清掉了，那一层就只剩"这里有过一条"。
- 向 connector 取回的层存原文，限长，最多五条。
- 体积按最终交给模型的文字和链接合计，计入一批的上限。超时之后才回来的结果不改已经开始的运行。
- 分批规则不变：仍按直接回复的那一条和提问人分，不因为两条消息有同一个更早的祖先就合成一次运行。同一个人、同一个会话里的几条消息共用一次查找。

### 3.4.1 agent 的答复回复的是哪条

- 先在同一个会话"说过的话"里按回执找到那条答复，再按它对应的发件记录找**当时实际发送用的地址**。只有"普通群里回复某条消息"这种地址里的消息编号，才是它回复的上一条。
- 授权后接着处理的答复，用的也是那次发送的地址。
- 这些都不算：会话当前最新的消息、授权回调、回执自己的编号、话题的第一条。
- 自然终点：私聊里的普通发送、仅一人可见的卡片、系统的固定提示、审批卡片、话题、发件记录已清掉。能认出是自己的旧答复但找不到发件记录时，显示这条答复，链到此为止。

### 3.5 飞书这一侧

- 取消息的接口（`GET /im/v1/messages/:id`，应用身份）本来就返回 `parent_id`，不需要新权限。
- 判断"本人写的"的条件不变：同一个群、发送者是用户、`open_id` 和组织都和提问人一致。
- 判断"应用自己写的"：发送者类型是应用且就是这个应用。
- 话题里的消息仍然不产生 `replies_to`（飞书在话题里每条都指向话题第一条，分不清是不是回复），所以话题里没有回复链，和现在一样。
- 私聊里所有消息 Brain 都收得到，链全部来自自己的记录，不会去问飞书。

## 3.6 分两步做

**第一步（先解决今天的场景）**：只 @ 的那条 → 取回他本人写的"说了啥？"以及它回复的是哪条 → 那一条如果是 agent 已送达的答复或他本人在记录里的消息，就把这两层交给模型。模型根据自己那条总结直接回答，这一步的验收是**文档读取零次**。追问总结里没有的细节时，走现有的出处判定和本人授权去重读。这一步不需要回溯 agent 更早的发件记录，也不改工具的选文档规则。

**第二步**：完整的五层、跨过别人的消息、3.4.1 的回溯、链上多篇由模型选。

### 3.7 另记一项，和第二步一起处理

群里被回复的那一条如果是本人没 @ 的消息，它的原文会写进这一轮的对话记录，所以同一个群里下一个提问人的运行也可能看到这句中间问话（Codex 对 a072dbb 的复核）。这是第一层就有的行为。第二步里把它改成和更早那一层一样：只存指向，按当前提问人决定是否展开。

## 4. 不做的

- **不给模型一个"读群聊记录"的工具。** 那是更彻底的 agentic 做法，但会把别人写的字交给以某个人身份行事的运行，之前专门挡住过。
- 不超过五层，不为取链延长运行开始前的等待。
- 不改"谁能让机器人读什么"：仍然只有本人贴的链接、本人的授权。

## 5. 代价

- 群里每条"回复的回复"最多多几次飞书调用（链上不在记录里的层数，上限五），都在三秒时限内。
- 模型的输入多出链上的文字，有上限。
- 改动三处：走链（Brain）、取一条消息时多返回两样（飞书 connector）、工具认链上的文档。

## 6. 验收场景

- 今天的场景：贴文档并 @ → 机器人总结 → 回复那条说"说了啥？"（不 @）→ 回复"说了啥？"只 @。机器人根据自己那条总结直接回答，不反问。
- 同上，但第二步问的是总结里没有的细节：机器人重读那篇文档再答。
- 链上有别人的消息：那一层只显示"有一条别人的消息"，更早的本人消息仍然可见。
- 链上有两篇本人贴的文档：模型选一篇读；它传了一篇不在链上、也不在他最近贴过的链接里的，工具拒绝。
- 链超过五层、中途超时、某层已被撤回：给出拿到的部分并说明不完整，不报错。
- 回复的是别人贴链接的消息：读不到那篇，和现在一样。
- 私聊里的两层回复：链来自自己的记录，没有飞书调用。
- 话题里：没有回复链，行为不变。
- 隔着群友的一条回复：更早的本人消息可见、其链接可选，群友那一条不可见。
- 链上有 agent 给另一个人的总结：作为上下文显示，不带来可读的文档。
- 靠回复链读过一篇旧文档之后，另发一条无关的追问：借不到那篇旧链接。
- 靠链上的文档发起授权，授权后接着处理：读的仍是那一篇。
- 链成环、中途过期：停在那里，不报错。
